## [critical/A] materials-1 — Every material in the project has a single constant roughness — 0 roughness maps, 0 normal maps, 0 anisotropy, 0 edge wear, 0 dirt
- file: `t1_mats.py`  locus: def simple() line 39; build_all() lines 385-439; the whole file  effort: heavy
- evidence: Dumped all 28 materials from a live Blender build. 25 have exactly 2 nodes (Output + Principled) with a constant Roughness, no image/procedural texture and an unlinked Normal socket: cream, wheelcream, bumpercream, roundelred, countercream, red, chrome, chrome_dull, glass, rubber, tyre, wheelred, capred, capwhite, whitewall, canvas, interior_dark, seat, timber, amber, ruby, lens, reflector, steel, white_gloss. calidad and script link only Base Color. T1_paint is the only material with a linked Normal, and its Roughness is still a constant 0.420 (t1_mats.py:214). Anisotropic = 0.0 on all 28. grep over t1_mats.py returns zero hits for pointiness, ambient occlusion, anisotropic, dust, dirt, wear, scratch, voronoi. Rendered consequence in out/r4d_side.png (ortho, 4.503 mm/px): 5x5 local luminance std over 52,147 px of clean red flank = 0.49/255 median, 0.73 at p90 — i.e. 0.19% modulation, at the dither floor. In out/r4d_front.png the entire front bumper blade (5600 px) spans sRGB 186-194, a range of 8 code values, 5x5 local std 0.474. SPEC §3 locks the finish as 'WEATHERED — chalky, sun-faded, uneven, chipped edges, dusty lower body'; no node in the project implements any of those five words.
- fix: Build one shared weathering node group and mix it into every painted/metal material: (a) a 2-4 octave noise at 0.02-0.15 m driving Roughness over 0.30-0.60 (never a constant); (b) Geometry->Pointiness through a Map Range to drive an edge-chip mask that swaps Base Color to primer grey/bare steel on convex edges (bumper crown, arch lips, door edges, drip rail); (c) a fine 0.3-0.8 mm noise into a Bump for real orange peel. Apply at minimum to T1_paint, cream, bumpercream, wheelcream, countercream, capred, roundelred.

## [critical/A] apertures-2 — cut() rollback guard cannot detect anything short of total destruction, and is structurally blind to gap cutters
- file: `build.py`  locus: cut(), line 38-57; threshold `if after < before * 0.6` line 47  effort: moderate
- evidence: Instrumented every one of the 22 cutters at both subdivision levels. The worst legitimate single-cutter vertex ratio is 0.9911 at T1_SUB=1 (arch11, 28382 -> 28128) and 0.9875 at T1_SUB=2 (arch11, 113522 -> 112105). The guard fires at 0.60, so a cutter could delete 39 % of the shell - both wheel tubs, the whole roof - and be recorded as a success. Worse: the five panel-gap cutters ADD vertices (gap_door1 +817 / +1171, gap_cargo +698 / +986, gap_englid +970 / +1832), so for those the guard's inequality is never even approached, and a boolean that no-ops (Blender's EXACT solver returning the input mesh unchanged) yields delta = 0 and passes silently. I added a digest check (vert count, face count, coordinate sums) and confirmed no cutter is currently a no-op - but nothing in the build would tell you if one became one. FAILED_CUTS was empty at both levels; verify.py row 9 only covers the rollback path, never the silent path.
- fix: In cut(), after apply_mods, compare a cheap mesh digest (len(verts), len(polys), sum of coords) with the pre-boolean digest and append to FAILED_CUTS on equality - a cutter that changes nothing has failed. Additionally replace the 0.6 ratio with a per-cutter expected sign: aperture cutters must reduce face count, gap cutters must increase vertex count by at least 2x the outline length / mean edge length. Also count non-manifold edges and zero-area faces after each cut and roll back on any increase.
